# MelloUI audit: Core, Backup, Config, UIModifications, DarkMode, Fonts, Tweaks, Stats, Vendor, Media, TOC

Read-only audit, 2026-09-22. Every line of the listed files was read. Only traceable defects are listed; style and hypotheticals omitted. Paths are relative to `F:\Download-Backup\Project Web\MelloUI`.

## HIGH

### H1. The baked default profile does not produce its intended state (Dark Mode and Bar Textures come up ON)
- `Media/Profiles.lua:7` stores the driven modules' state as flags: `!DarkMode=b0`, `!BarTextures=b0`, `!Fonts=b1`, and has **no** `UIModifications.qol_DarkMode` / `qol_BarTextures` entries (baked before those modules were folded into UI Modifications).
- `Core/Core.lua:608` applies the profile (`DeserializeSettings` writes `db.enabled.DarkMode=false`), then `Core/Core.lua:617-620` runs the init pass; UIModifications' `OnEnable` (`Modules/UIModifications.lua:627-629`) calls `Apply` -> `Want` (`:587-593`), which overwrites `db.enabled[<driven>]` from its own `qol_*` settings, whose defaults are all `true` (`:84-90`). Net: on a fresh install DarkMode and BarTextures are enabled although the profile said off (and BarTextures' `texture=Minimalist`, `healthColor=reaction` from the same profile then apply).
- Generalisation: any `!X` flag for a hidden/driven module in a profile or in the macro backup is dead weight; `Apply` overrides it at every login, every umbrella toggle and every `RestartModules`.
- Fix: re-bake the profile with `UIModifications.qol_DarkMode=b0;UIModifications.qol_BarTextures=b0` (drop the three `!` flags); in `Core/Backup.lua:174-177` skip the flag for modules with `module.hidden` (they are derived). That also removes up to ~600 chars from the backup (see M2).

### H2. Slash profile commands lowercase the profile name
- `Core/Config.lua:1692` lowercases the whole message before `save|load|delete|default <name>` (`:1711-1725`). A profile saved from the UI (`:1290`, case kept) or the bundled `"MelloUI"` cannot be loaded, deleted or set default from chat: `/mello profile load MelloUI` -> `LoadProfile("melloui")` -> "No profile 'melloui'". `/mello profile save My Set` silently stores `"my set"`.
- README `Slash commands` table documents these commands without this caveat.
- Fix: lowercase only `cmd` and `sub`; take `name` from the untrimmed original message (`msg:match("^%S+%s+%S+%s*(.-)$")`).

### H3. Backup overflow writes a truncated prefix that is restored as wrong values next login
- `Core/Backup.lua:258-275`: `WriteChunks` writes chunks 1..8 (2000 chars of the prefix) and only then returns `false, "settings too large ..."`. The macros now hold the prefix cut at an arbitrary character.
- `Core/Backup.lua:333-337`: that error is stored but **not printed** (only "no free account macro slot" is), and `lastWritten` stays stale so the failing write repeats on every change.
- Next login, `RestoreFromBackup` -> `DeserializeSettings` (`:182-206`) parses the cut tail as a real entry: `Tweaks.worldTextScale=n0.` -> `tonumber("0.")` = 0 -> `SetCVar("WorldTextScale","0.00")` (invisible combat text); `X.flag=b` -> `false`; a cut font path -> an invalid face; a cut `t...` positions blob -> partial positions.
- Fix: in `WriteBackup`, refuse when `#text > CHUNK_SIZE * MAX_CHUNKS` before touching any macro, keep the previous macros, and `Print` the error; optionally cut chunks only on `;` boundaries so a partial read is still well-formed.

## MEDIUM

### M1. On a fresh install the addon "restores" its own first backup write and restarts every module
- `Core/Backup.lua:393-401` (`UPDATE_MACROS`): guard is `dbIsTemporary and not restoredFromBackup`. On a fresh install nothing was restored at login, so `restoredFromBackup` is nil. The first write (`ShowMenuButtonTip` at PEW+8 s -> `ScheduleBackup` -> `WriteBackup` 3 s later, `Core/Core.lua:175-185`, `:637-640`; or the first setting change) edits the macros, which fires `UPDATE_MACROS`; the handler reads back the text it just wrote, `applied > 0`, then `RestartModules()` (OnDisable+OnEnable of every enabled module, ~34) and prints "Settings restored from the macro backup." ~11 s into the first session.
- Fix: in the handler skip when the read text equals `lastWritten` (both `RestoreFromBackup` and `WriteBackup` set it), or set `self.restoredFromBackup = true` on a successful write.

### M2. Backup capacity (8 x 250 = 2000 chars) versus what the settings can need
Estimated encoded sizes (module + key + type prefix + separators, from each module's defaults):
- Scalar settings across all modules if every one differs: ~2.9 k (DarkMode 376, QuestList 301, BarTextures 265, Tooltip 257, Route 236, BarText 221, Chat 186, Tweaks 171, CooldownText 165, UnitFrames 146, Services 143, Stats 142, Nameplates 122, Vendor 79, ...).
- Fonts: each chosen role is a full path with doubled backslashes (`Fonts.fontText=sInterface\\\\AddOns\\\\MelloUI\\\\Media\\\\Fonts\\\\Prototype.ttf` ~75 chars), four roles ~300.
- UIModifications: 36 toggles (`reskin`, 21 panels, 13 `qol_*`, `unlock`) ~30 chars each, ~1.1 k if all flipped.
- Driven-module flags written by `Apply` (`Modules/UIModifications.lua:587-608`): reskin off alone = 21 `!XPanel=b0` entries ~380 chars, umbrella off = 34 entries ~600 chars, all redundant with `UIModifications.reskin=b0` / `!UIModifications=b0`; `!Fonts=b1` always (see M5).
- Window positions (`Modules/UIModifications.lua:464-465`): `x`/`y` are raw floats (`x:n123.45678901234`), so one entry is ~80-95 chars; 21 windows + minimap/tracker/meter/chat shells -> ~2 k on their own.
- The baked profile is already ~830 chars. Reskin off + a dozen moved windows + one custom font overflows -> H3.
- Fixes: skip hidden modules' flags (H1); round `x`/`y` to one decimal and omit `relPoint` when equal to `point` in `:464`; stop re-emitting keys that are not in `module.defaults` (see L1).

### M3. Configurator "Defaults" button aliases table defaults into the live settings
- `Core/Config.lua:845-848`: `for key, value in pairs(module.defaults) do MelloUI:NotifySettingChanged(module.name, key, value)` assigns `db[key] = value` (`Core/Core.lua:336`). For UIModifications `defaults.positions = {}` (`Modules/UIModifications.lua:72`) this makes `db.positions` **the same table** as `module.defaults.positions`.
- Every later drag (`Modules/UIModifications.lua:460-469`) then writes into the defaults table. `ApplySettingsText` (`Core/Core.lua:525-528`) and `GetModuleDB` (`:282`) copy defaults into the db, so a profile load resurrects the old positions; `ResetPositions` (`:550`) replaces `M.db.positions` with a new table, leaving the defaults polluted.
- Fix: in the Defaults handler pass `CopyTable(value)` for table defaults (or skip table keys).

### M4. `Apply` enables the driven modules in PANELS-then-TWEAKS order outside the init pass
- `Modules/UIModifications.lua:595-608` iterates `PANELS` (UnitFramePanel, ...) before `TWEAKS` (BarTextures, Fonts, ...). `Want` only defers to TOC order while `MelloUI.initializingModules` is set (`:587-593`). Any other path calls `SetModuleEnabled` immediately: toggling UI Modifications on from its tile / `/mello enable UIModifications` (`OnEnable` -> `Apply`), a profile load where the umbrella was off (`Core/Core.lua:535-539`), `RestartModules` (`:441-448`, M1 path). This is exactly the order `initializingModules` was added to prevent (`Core/Core.lua:612-616`: UnitFramePanel read bar layers before BarTextures set them).
- `RestartModules` hides it by restarting each child a second time in TOC order (every driven module gets OnDisable/OnEnable twice); the `SetModuleEnabled` path has no second pass.
- Fix: in `Apply` iterate `MelloUI:IterateModules()` (TOC order) and `Want` only names present in a `driven` lookup, or move the `TWEAKS` loop before the `PANELS` loop.

### M5. Fonts: `enabledByDefault = false` disagrees with the umbrella's `qol_Fonts = true`; the early world-font hook never sees restored settings
- `Modules/Fonts.lua:133` vs `Modules/UIModifications.lua:86`. The umbrella forces Fonts on at every login, so `!Fonts=b1` is serialised in every backup/profile (`Core/Backup.lua:174-177`), and `/mello list` / the module's own default are misleading.
- `Core/Core.lua:588-592` runs `OnAddonLoaded` at ADDON_LOADED using `IsModuleEnabled` and default settings; `RestoreFromBackup` runs only at PLAYER_LOGIN (`:605`) and does not re-run `OnAddonLoaded` (only `AdoptSavedVariables` does, `:425-430`, which never happens on this client). So `Fonts:OnAddonLoaded` (`Modules/Fonts.lua:464-467`) always sees `fontText/fontDamage = "default"` and does nothing; world fonts are only set at PLAYER_LOGIN through `OnEnable`.
- Fix: `enabledByDefault = true` for Fonts (or skip hidden modules' flags); in the PLAYER_LOGIN handler, after a successful `RestoreFromBackup`, run the same `OnAddonLoaded` pass as `AdoptSavedVariables` does.

## LOW

### L1. Stale keys are accepted and re-emitted forever
- `Media/Profiles.lua:7` contains `Fonts.worldDamage=b1`; no module has that key. `Core/Backup.lua:196-199` stores it in `db.modules.Fonts`; `:162` treats `defaults[k] == nil` as "differs", so it is written into every backup and profile from then on. Fix: in `DeserializeSettings` skip `settingKey` not present in `module.defaults`.

### L2. Dark Mode toggling a component on ignores kit cover
- `Modules/DarkMode.lua:935-937`: `if value then appliers[key]()` with no `Covered(key)` check (OnEnable `:903` checks it). Turning e.g. "Action Bars" on while ActionBarPanel covers `actionbars` darkens the kit art, against the rule at `:153-154`. Fix: `if value and not Covered(key)`.

### L3. Personal resource display list has holes
- `Modules/DarkMode.lua:435-439`: `{ a, b, c }` with nil entries; `ipairs` stops at the first nil, so if `HealthBarsContainer.healthBar` is absent, `PowerBar` and `AlternatePowerBar` are never shaded. Fix: append with `if x then list[#list+1] = x end`.

### L4. Slash command documentation mismatches
- In code, not in README's table: `/mellolog [clear]` (`Core/Core.lua:152-160`), `/mello help` (`Core/Config.lua:1847`), and the debug commands `/kitdemo` (`Modules/Kit.lua:3538`), `/uftest` (`Modules/UnitFramePanel.lua:937`) and 21 `/xxdump` commands (README only mentions `/mmdump` and `/trdump` in prose).
- In README but not on the in-game Help page: `/mello dump`, `/mello cpu` (`COMMANDS`, `Core/Config.lua:143-155`; they are printed only by `/mello help`, `:1852-1853`); `/mellolog` is on neither.

### L5. Tweaks restores WorldTextScale to a constant, not the prior value
- `Modules/Tweaks.lua:345-348`: `OnDisable` sets the CVar to 1; `OnEnable` (`:342`) never captured the value before the module touched it. Fix: read `C_CVar.GetCVar("WorldTextScale")` once before the first apply and restore that.

### L6. Late saved-variable adoption drops table settings
- `Core/Core.lua:401`: `real[k] == module.defaults[k]` is never true for a table value (each db gets its own copy via `ApplyDefaults`), so `positions` restored from the backup into the temporary db are not carried over if the client ever delivers `MelloUIDB` late. Moot while SVs are never read back, but the code path exists (`:642-660`).

### L7. `/mello <unknown>` closes the window
- `Core/Config.lua:1855` -> `OpenConfig("foo")` -> `target = nil` -> `:1611-1613` hides an open window instead of reporting an unknown module.

## Checked and found consistent
- All option keys in DarkMode, Fonts, Tweaks, Stats, Vendor, UIModifications have defaults; all dropdown values are scalar strings the encoder can store; the only table setting (`positions`) is one level deep with scalar leaves, as the encoder requires.
- Disable->enable cycles: DarkMode (`hooksInstalled`, `coverWatched`, weak-keyed per-frame hook sets), Fonts (`panel.hooked`, `chatHooked`), Tweaks (`callbacksRegistered`, `bagHooksDone`), Vendor/Stats (register/unregister) do not duplicate hooks, timers or event registrations. UIModifications' `MakeMover` is guarded by `movers[frame]`.
- Movers only attach to unprotected frames (UI panels, chat frames, MinimapCluster, tracker, damage meter), so `PutBack`'s SetPoint/SetScale from hooks does not hit secure frames in combat.
- Every file listed in `MelloUI.toc` exists; the sounds, fonts and textures referenced by Config/CustomFonts/Profiles exist; `MelloUI_KitLayout.pieces["inputs/slider_mid"]` and every `Kit:` method the configurator calls exist with matching arity; `Kit.scale` is initialised at load.
- Secret-value handling: `Core/Core.lua:62-94` (`Print`) and `Modules/Fonts.lua:202-216` guard the paths that can see secrets; nothing in the audited modules compares or concatenates unit/target API values.
